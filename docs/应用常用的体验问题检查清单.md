用于后续检查全局已有题目。记录可复现的问题、原因、通用处理方法与验收结果；代码检查通过不等于用户体验验收通过。

## 连续假名造成注音错位

状态：待用户验收（2026-10-25）；本条是待确认素材，用户认可后再标记为已验收案例。

- 页面：`/tools/course-detail-preview.html?lesson=31&part=practice`
- 题目 ID：`l31-p1-a3-q4`
- 原句：母は時々財布を忘れます。
- 现象：「はは」错挂到「時々」上。
- 原因：整句读音「はははときどきさいふをわすれます」本身正确，但自动注音以假名助词为边界，首次匹配「は」时命中了「母」的读音内部，导致后续读音错位。
- 修复：使用现有 RichText 的逐词 `kana` 字段，显式标注「母→はは」「時々→ときどき」「財布→さいふ」「忘→わす」，助词「は」「を」和送假名「れます」保持普通文本。保留整句读音，不通过修改正确读音来迁就切分算法。
- 通用方法：对重复假名、助词与词内读音相同、数字读法等存在歧义的句子，优先使用逐词注音。不能仅凭整句读音可靠推断所有词界，不应以“取第一次/最后一次匹配”统一替换规则。
- 后续全局检查：筛选仅有整句 `promptKana` 的题目；重点核对重复假名和短助词边界；逐词对照正文与 ruby，检查漏标、错挂、多余标注和相邻词串读。显式注音的词也需核对读法及送假名。
- 验收：用户确认这道题显示为「母（はは）は時々（ときどき）財布（さいふ）を忘（わす）れます」，并确认页面布局没有异常。

## 生词连续点击时只能有一段发音

状态：代码与模拟检查通过，待页面试听验收。

- 范围：课文、语法、练习页。
- 通用方法：新点击立即停止旧音频与旧定时器；失效的异步加载回调不能启动播放或语音合成兜底；按片段结束位置停止，离开页面取消播放。
- 验收：先点 A，未结束时点 B，再快速点 C；只听到最新选择。慢网络下重复操作，旧请求完成后不得抢播。单独播放一个词，不应继续播出源音频中紧随的下一个词。
- 额外核对：若只点一次仍听到相邻词，检查 `audioSegment.start/end` 本身是否标注过宽，不应仅调整播放器掩盖数据错误。

## 语法与表达导航序号必须来自原始条目

状态：已修复，待全局页面验收。

- 页面：`/tools/course-detail-preview.html?lesson=33&part=grammar`、`/tools/course-detail-preview.html?lesson=38&part=grammar`；同时适用于应用内 `/lesson/:lesson/grammar`。
- 现象：语法列表按“有例句的条目”或筛选后的数组重新编号，导致第二个语法点在第一个语法点没有例句时显示为 1；“表达及词语讲解”直接显示 `词语：～かしら`，缺少对应的序号。
- 原因：导航使用筛选结果的 `groupIndex + 1`，没有使用条目的稳定 `gN/eN` 编号；标题也没有统一去掉类别前缀和已有序号。
- 修复：应用内导航和课程预览页都优先从条目 id（`gN` / `eN`）取编号，兼容从旧的带数字标题中解析；显示为“编号 + 去掉类别前缀后的标题”，例如 `2.～かしら`。
- 通用方法：任何从课程数据过滤、分组或丢弃空例句后渲染的列表，都不能用渲染数组下标代替教材编号；标题清洗必须保留原始条目与稳定 id 的对应关系。
- 后续全局检查：逐课检查语法条目存在“无例句、无补充例句、只有课文关联例句”等情况时，后续条目编号是否保持教材编号；检查表达/词语标题是否有序号、是否残留 `表达：` / `词语：` / `寒暄语：` / `对比：` 前缀；续页 ID（如 `e4-cont`）也必须继承数字序号；抽查 lesson 1、23、27、33、34、38、43。
- 验收：确认 lesson 33 中第二个语法点仍显示为 2，`～かしら` 显示为 2.～かしら，且点击后仍定位到原条目。

- 补充案例：lesson 38 的 `e4-cont` “ら抜き言葉（续）”曾缺少编号，属于续页 ID 只匹配完整 `eN` 的同类问题；修复后应显示为 `4.ら抜き言葉（续）`。

## 语法页例句提取必须以教材图片为准

状态：第 40–48 课已重提取并生成音频，待逐课内容验收。

- 范围：`/tools/course-detail-preview.html?lesson=40..48&part=grammar`，以及对应的 `data/ocr/lessonN-grammar-examples.json` 和 `lessonN-grammar-audio.json`。
- 现象：语法页只提取了部分例句，漏掉跨页语法点、表达页句子或教材反例；也可能把变形表、中文说明、词汇列表误当成可朗读句子。
- 原因：把 OCR 结果或已有 JSON 当成最终句子来源，没有逐页对照教材图片；跨页续组和“表达及词语讲解”页容易被截断。
- 通用方法：教材图片是唯一事实来源；逐页建立语法组，保留所有可见日语例句、对话顺序、标点和 × 反例，排除表格/中文说明/词汇表；数据审核通过后再调用 Azure 音频脚本。
- 后续全局检查：逐课核对语法页图片中的语法标题、例句数量、跨页续组和反例标记；确认每个去重后的句子都有 manifest 记录且 MP3 路径存在；预览页不得显示“标准例句音频尚未生成”。
- 验收：lesson 40–48 已重新写入例句 JSON；共 285 条原始例句、282 条去重句子，9 个 Azure manifest 的全部路径均已校验存在。
